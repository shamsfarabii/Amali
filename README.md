# Amalī

A minimal, offline-first app for keeping a personal dua collection—Arabic text, optional pronunciation, Bengali meaning, and source notes.

Built with Expo (SDK 57), Expo Router, TypeScript, and SQLite. Data stays on your device; export and import plain JSON backups when you change phones or want a safety copy.

## Features

- **Rich entries** — Title, Arabic, pronunciation, Bengali meaning, and source for each dua.
- **Folders** — Group duas (morning, evening, travel, and so on) and filter the list by folder or “unfiled.”
- **Search** — Finds matches across all fields; Arabic search ignores common diacritics.
- **Reading** — Adjustable text size and a choice of bundled Arabic typefaces; Bengali and UI text use Hind Siliguri.
- **Backup** — Export the full collection to a file; import with merge or replace, preview, and validation.
- **Private** — No account, no network requirement for daily use.

## Design

- **Palette.** “Lapis & porcelain”: tile-work blues on porcelain white, and a deep lapis night palette in dark mode (follows the system). All colors live in `src/theme.ts`.
- **Fonts.** The Arabic font is chosen in Settings: Naskh ([Noto Naskh Arabic](https://fonts.google.com/noto/specimen/Noto+Naskh+Arabic), default), IndoPak ([Noorehuda](https://www.noorehidayat.org/), see `assets/fonts/Noorehuda-LICENSE.txt`), [Amiri](https://fonts.google.com/specimen/Amiri), and [Scheherazade New](https://fonts.google.com/specimen/Scheherazade+New). Each has a size and line-height adjustment in `arabicFonts` (`src/theme.ts`) so they read at a similar size. Bengali and all interface text use Hind Siliguri. All fonts are bundled for offline use.
- **Icons.** SF Symbols on iOS, Material Symbols on Android (`expo-symbols`), mapped in `src/components/Icon.tsx`.
- **Logo.** A gold crescent inside an eight-point star on lapis. Icon and splash assets are generated by `scripts/generate-icons.py` (`python3 scripts/generate-icons.py assets`, requires Pillow). Display name and tagline live in `src/brand.ts`.
- **Ornament.** An eight-point star separates Arabic from its meaning on detail and welcome screens.
- **Styling.** Components use theme-aware styles via `useThemedStyles(makeStyles)`.

## Run

```bash

npx expo run:ios       # or: npx expo run:android  (local development build)
```

## GitHub Releases (automatic APK)

Every push to `main` runs [`.github/workflows/android-release.yml`](.github/workflows/android-release.yml): **GitHub Actions** installs dependencies, runs `expo prebuild`, builds `assembleRelease` with Gradle, and publishes a new [GitHub Release](https://github.com/shamsfarabii/Amal-/releases) with **Munajat.apk** attached.

No Expo/EAS account is required for CI. Commit and push the workflow to `main` to enable it.

Release tags look like `v1.0.0-build.42` (version from `app.json` plus workflow run number). You can also run **Actions → Android APK Release → Run workflow** manually.

### Optional: production signing (GitHub secrets)

Without secrets, the APK is release-built but signed with the default debug keystore from prebuild (OK for sideloading on your own devices). To use your own upload key, add these **Settings → Secrets and variables → Actions** secrets:

| Secret | Description |
|--------|-------------|
| `ANDROID_KEYSTORE_BASE64` | Base64 of your `.jks` / `.keystore` file (`base64 -i upload.keystore \| pbcopy` on macOS) |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | Key alias |
| `ANDROID_KEY_PASSWORD` | Key password |

Generate a keystore locally if needed:

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore upload.keystore -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

## Structure

```
src/
  app/          routes only (Expo Router): welcome, list, detail, form, folders, settings
  components/   presentational UI
  state/        DuaProvider (collection) and SettingsProvider (font, welcome, scale)
  db/           SQLite: migrations + repositories (only place with SQL)
  backup/       export, import, validation, and merge planning
  types/        Dua, folder, and settings models + input validation
  utils/        text normalization for search, id generation
```

Dependencies point downward only: `app → state → db/backup → types`.

## Backup format

```json
{
  "format": "custom-dua-backup",
  "version": 2,
  "exportedAt": "2026-09-25T10:00:00.000Z",
  "count": 1,
  "folders": [
    { "id": "uuid", "name": "সকালের দোয়া", "createdAt": 1758794400000, "updatedAt": 1758794400000 }
  ],
  "duas": [
    {
      "id": "uuid",
      "title": "…",
      "arabic": "…",
      "pronunciation": "",
      "bengali": "…",
      "source": "",
      "folderId": "uuid or null",
      "createdAt": 1758794400000,
      "updatedAt": 1758794400000
    }
  ]
}
```

Version 1 backups (no titles, pronunciation, or folders) still import.

### Import flow

1. **Checks the file.** Files over 5 MB are rejected. JSON is parsed safely.
2. **Validates everything.** `format` and `version` are checked, then each entry. Invalid entries are skipped and counted.
3. **Plans the import.** Nothing is written yet. Duplicates (same id, or same content ignoring diacritics) are skipped. Newer copies of existing duas replace older ones. A folder with the same name as one you already have is merged; a dua pointing at a missing folder ends up unfiled.
4. **Asks you first.** A preview is shown; you choose **Merge** or **Replace all**.
5. **Writes in one SQLite transaction.** If anything fails, nothing changes.
6. **Keeps a safety copy.** Before **Replace all**, the current collection is saved to `pre-import-backup.json` in the app documents directory.

## Adding a field or table later

- Bump the schema version in `src/db/database.ts` and add an `if (version < N)` migration.
- If the backup shape changes, bump `BACKUP_VERSION` in `src/backup/format.ts` and teach `validate.ts` to read older versions.
